# Handoff: Task 5c, Misi (story adventure) prototype

*17 Nov 2026 · Claude Code → reviewer (Codex)*

## Context
On 17 Nov 2026 Yang approved "Misi Kata", point-and-tap story quests, after a proposal comparing an adventure map, story quests and a walk-around RPG. The decisions:
1. Misi is **optional per unit, unlocked after Uji**.
2. Character lines are **in BM with 🌐 tap-to-translate** (EN/中文).
3. **Prototype now**, before task 7.
4. Prototype theme: **Unit 2 waterfall holiday**.

There is no timer and no failing: every challenge is a word question, and a wrong choice gets a kind hint. Background: `CLAUDE.md` §1, §2 (content originality, unreviewed content never in production), §6 (validation) and §9 (conventions). This is not a git repo, so the files are listed below.

## What was built
- **Content format** (`apps/web/src/content/schema.ts`, `QuestSchema`), one `quest.json` per unit:
  - **Quest:** characters (id, name, portrait), scenes (title, background, props, steps) and a reward picture.
  - **Props:** stickers placed at x/y/size %. They can be `hidden` until revealed.
  - **Steps:**
    - `say`: a line;
    - `choose`: fill the `___` in a BM line with the chapter word, from 3–4 options; can `reveal` a prop;
    - `find`: tap the prop that matches the chapter word.
  - **Review flag:** `reviewed: false` until Yang reviews it. The loader hides unreviewed quests in production, like chapters.
- **Validation** (`content/validate.ts` `checkQuest`, wired into `scripts/validate-content.ts`). It walks the quest in order, tracking which props are visible, and checks:
  - speakers exist;
  - each `choose` line has exactly one `___` in **BM, EN and 中文**, so a translation can never give the answer away;
  - the word's text is among the options exactly once; options are distinct;
  - reveals point at hidden props;
  - each `find` answer is visible at that step, with at least 3 props to choose from;
  - every chapter word is practised (a warning if not).

  `--strict` fails on an unreviewed quest; quest images may be PNG until the WebP step in task 9.
- **Content:** `content/tahun-3/unit-02/quest.json`, "Pengembaraan di Hutan" (Forest Adventure). It has 3 scenes (forest edge → river → upstream at the waterfall) and 12 challenges (10 choose + 2 find), using **all 12 Unit 2 words**. The family is Malay: cousin Aina, Ayah, Mak Long. No title or scene name contains an answer. The BM is an original draft that **needs Yang's review**.
- **Art:** `content/tahun-3/unit-02/quest-prompts.json` (style + kinds: background / portrait / prop / reward) produced 11 PNGs, generated by Codex into `unit-02/quest/`.
- **Engine** (`engine/quest.ts`):
  - `startQuest(quest, seed)`: seeded option order;
  - `currentStep`, `optionsFor`, `visibleProps`;
  - `answerStep`: a wrong answer is crossed out (repeat taps ignored); a right answer → `solved`, and reveals a prop if the step has one;
  - `nextStep`: only after a `say` line or a solved challenge;
  - `questSummary`: first-try count → stars; words to practise.
- **Screen** (`games/Misi.tsx`, lazy-loaded): intro (cover, BM intro + 🌐, Start) → play → result.
  - **Play:** scene picture with sticker props (tappable only in `find` steps), plus a dialogue card with portrait, name, BM line, blank, 🌐 and options. A wrong choice shows "Hmm, bukan itu. Petunjuk: <the word's BM meaning>"; with 🌐 on, the hint also appears in EN/中文. **Next** appears only for a line or a solved challenge.
  - **Result:** the reward photo, stars, first-try count and words to practise.
  - **Translation toggle:** remembered in localStorage.
- **Entry points:**
  - the route `#/lab/misi/<chapterId>`;
  - a dev/staging-only Home link;
  - a **Misi card on the unit screen**, locked until Uji is done, then linking to the adventure (shown only when the unit has a quest that is visible in that build).
- **Not saved yet** (prototype): progress, stars and the reward. These come with the collectibles in task 7.

## Decisions worth challenging
1. **The hint is the word's BM meaning** from the chapter (no per-step hint text), so content stays small.
2. **Props are stickers placed by coordinates**, not hotspots in the background art. We control positions, but they look pasted on.
3. **Stars count first-try answers only**, and the minimum is 1.
4. **`find` lines name the target word** ("Cari barang untuk memancing") and test its meaning through the object. **`choose` lines hide the word** and test recall in context.
5. **The Misi route lives under `lab`** for now; the unit-screen card links there.
6. **The quest JSON is bundled eagerly** in the main chunk (small); its images load on demand.

## What I'd like from the review
- **Bugs:** state transitions, reveal/visibility, double taps, the translation toggle, focus, StrictMode, wrong-answer handling.
- **Validator gaps:** content that would pass but break or mislead a child.
- **The BM draft:** natural Tahun 3 language, distractors that might also be correct, translations that leak answers.
- **For the child:** accessibility (screen readers, focus, labels, contrast on the picture), and weak tests.

Rank by severity, cite `file:line`, give a failure scenario, and keep it concise.

## Review outcome (Codex review: `task-05c-misi-prototype.review.md`)
All 5 findings were valid and are fixed. Codex also reviewed the BM dialogue, distractors and EN/中文 translations and found no text errors. Regression tests are marked "task-05c review #n".

| # | Finding | Fix |
|---|---|---|
| 1 | Medium: an option with extra spaces (`" sepupu "`) passed validation but could never be answered | The engine compares with `sameText` (case and whitespace normalised, like the validator), and `checkQuest` now rejects options with surrounding or double spaces |
| 2 | Medium: a direct Misi URL skipped the Uji unlock | `App.tsx` routes a unit's Misi only if `canOpenMisi(ujiDone, LAB_MODE)`; otherwise it shows the unit screen. `LAB_MODE` (dev or `VITE_SHOW_LAB`) is shared in `app/flags.ts`; Playwright builds with it, like staging |
| 3 | Medium: offline, quest art (PNG) wasn't cached, so find steps showed blank cards | Workbox runtime `CacheFirst` cache for images (300 entries, 90 days): any picture already seen works offline. Full precaching comes with the WebP step (task 9) |
| 4 | Low: focus landed on the line, which came after the props in DOM order, so keyboard and screen readers skipped the find answers | DOM order is now line → options → props → Next; CSS `order` keeps the picture on top visually |
| 5 | Low: `#/lab/misi/t3-u01` showed Unit 2's quest | Falls back to the first quest only when no unit is given; otherwise shows "no story adventure for this unit yet" |
